# Interop surfaces

Cyrs is a Rust library at its core. Every non-Rust consumer goes through
one of five adapters, all thin shells over the same
`cypher-lang-services` + `cypher-db` engine. Analysis logic lives in
the library crates; the interop crates only translate wire formats and
memory conventions. See [spec 0004](specs/0004-interop-surfaces.md) for
the normative contract.

---

## 1. Which binding do you want?

| You are…                                   | Use                             | Why                                               |
| ------------------------------------------ | ------------------------------- | ------------------------------------------------- |
| Web frontend / Monaco / CodeMirror         | `cypher-wasm`                   | Runs in-browser, no server round-trip             |
| Go / Node / Swift / Java (JNI) / C         | `cypher-ffi` (cbindgen)         | Stable C ABI, opaque handles                      |
| Python                                     | `cypher-py` (PyO3 wheel)        | Direct Rust, abi3-py310 single-wheel-per-platform |
| LSP client in browser                      | `cypher-lsp --features web-lsp` | Same LSP, `postMessage` transport                 |
| Editor highlighting (no LSP needed)        | `tree-sitter-cypher`            | Grammar-only, installable via nvim-treesitter / Helix |

All five produce identical diagnostics on the same input; the
integration tests in `demo/` assert bit-for-bit parity between
`cypher-wasm`, `cypher-ffi`, `cypher-py`, and the `cypher-agent` CLI.

---

## 2. WASM — `cypher-wasm`

A `cdylib` compiled to `wasm32-unknown-unknown` with a `wasm-bindgen`
JS wrapper. Exposes the agent v1 op surface as methods on a single
`CypherDatabase` class.

### Build

```sh
# one-off
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --locked

# full build + size-gate pipeline (cbindgen, wasm-opt, brotli)
cargo xtask wasm-build
```

Output lands in `demo/web/pkg/` (for the Monaco demo) or
`crates/cypher-wasm/pkg/` when built standalone.

### Minimal example

```js
import init, { CypherDatabase } from "./pkg/cypher_wasm.js";

await init();

if (CypherDatabase.protoVersion() !== 1) {
  throw new Error("proto mismatch");
}

const db = new CypherDatabase();
const result = db.check("MATCH (n RETURN n");
console.log(result.diagnostics);
// [{ code: "E0011", severity: "error",
//    message: "expected ')' to close node pattern", ... }]
```

Clean input returns `{ diagnostics: [] }`. Every method on
`CypherDatabase` mirrors the matching agent op (`parse`, `check`,
`complete`, `hover`, `format`, `rewrite`, `plan`, `explain`,
`schemaSet`, `schemaClear`); see spec 0001 §15 for the full wire table.

### Monaco integration

The [`demo/web/`](../demo/web/) page wires `CypherDatabase` into a
Monaco editor and renders diagnostics as markers. No bundler, no build
step — Monaco loads from a pinned unpkg CDN path and the wasm wrapper
loads as an ES module. Run with `npx serve demo/web` after the xtask
build.

### Size budget

Spec 0004 §4.2 caps the brotli-compressed `.wasm` at **2 MB**. Nightly
CI regenerates the artifact end-to-end and fails on breach. The
pipeline runs `wasm-bindgen`, `wasm-opt -Os`, and `brotli -q 11` in
sequence.

## 3. C FFI — `cypher-ffi`

A stable C ABI produced by cbindgen over a panic-safe `extern "C"`
surface. Every export wraps its body in `std::panic::catch_unwind`;
panics never cross the FFI boundary (spec 0004 §5.3).

### Build

```sh
cargo build -p cypher-ffi --release
```

Artifacts (relative to the workspace `target/release`):

| Target  | Artifact                                                  |
| ------- | --------------------------------------------------------- |
| macOS   | `libcypher_ffi.dylib`                                     |
| Linux   | `libcypher_ffi.so`                                        |
| Windows | `cypher_ffi.dll`                                          |
| any     | `libcypher_ffi.a` (static archive)                        |

Authoritative C header:
[`crates/cypher-ffi/include/cypher.h`](../crates/cypher-ffi/include/cypher.h),
regenerated by `cargo xtask cbindgen`. CI gates header drift with
`cargo xtask cbindgen --check`.

### Minimal example

```c
#include "cypher.h"
#include <stdio.h>
#include <string.h>

int main(void) {
    CypherDatabase* db = cypher_database_new();
    const char* src = "MATCH (n RETURN n";
    CypherDiagnosticList* list = cypher_check(db, src, strlen(src));

    size_t n = cypher_diagnostic_list_len(list);
    for (size_t i = 0; i < n; ++i) {
        const char* code = cypher_diagnostic_code(list, i);
        const char* msg  = cypher_diagnostic_message(list, i);
        uint32_t sl = cypher_diagnostic_start_line(list, i);
        uint32_t sc = cypher_diagnostic_start_col(list, i);
        uint32_t el = cypher_diagnostic_end_line(list, i);
        uint32_t ec = cypher_diagnostic_end_col(list, i);
        printf("[%s] %s at %u:%u-%u:%u\n", code, msg, sl, sc, el, ec);
    }

    cypher_diagnostic_list_free(list);
    cypher_database_free(db);
    return 0;
}
```

Build and run:

```sh
cc -I crates/cypher-ffi/include example.c \
   -L target/release -lcypher_ffi \
   -o example
./example
```

Output:

```
[E0011] expected ')' to close node pattern at 0:9-0:9
```

### Memory ownership

Rust allocates; the caller frees via the **paired** `_free` function.
Mixing allocators (e.g. `free()` on a Rust-allocated pointer) is
undefined behaviour. Full pairing table in the
[`cypher-ffi` README](../crates/cypher-ffi/README.md#memory-ownership-contract-spec-0004-52).

Accessor functions that return `const char*` (e.g.
`cypher_diagnostic_code`) return a **borrowed** pointer tied to the
owning opaque container; do not `free` it. `cypher_last_error()`
returns a thread-local pointer that is never `NULL`; on success it
points at the empty string.

### Non-C consumers

- Go: [`demo/ffi/go/main.go`](../demo/ffi/go/main.go) — cgo-based
  smoke test.
- Node: [`demo/ffi/node/index.js`](../demo/ffi/node/index.js) —
  `koffi`-based (pure-JS loader, no native build step).

Swift and Java (JNI) follow the same opaque-handle pattern; see spec
0004 §5 for the template.

## 4. Python — `cypher-py`

PyO3-built extension module, published as abi3-py310 wheels — one
wheel per platform covers CPython 3.10 → 3.13.

### Install

Once published:

```sh
pip install cypher
```

Until then, wheels ship as GitHub release assets. For local
development:

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install maturin pytest
maturin develop -m crates/cypher-py/Cargo.toml
```

`maturin develop` builds the cdylib and installs it under
`.venv/lib/python*/site-packages/cypher/`.

### Minimal example

```python
from cypher import CypherDatabase

db = CypherDatabase()
diags = db.check("MATCH (n RETURN n")
for d in diags:
    print(d.code, d.severity, d.message, d.range)
# E0011 error expected ')' to close node pattern (0, 9, 0, 9)
```

Clean input returns an empty list. `CypherDatabase` is a single
handle owning one interned `FileId`; the analysis cache is warm after
the first call.

### API surface

Methods on `CypherDatabase` (all mirror agent ops; spec 0001 §15):

- `parse(text) -> ParseResult`
- `check(text) -> List[Diagnostic]`
- `complete(text, offset) -> List[CompletionItem]`
- `hover(text, offset) -> HoverResult`
- `format(text) -> str`
- `rewrite(text, fix_ids) -> RewriteResult`
- `schema_set(toml) -> None`
- `schema_clear() -> None`

Module-level: `PROTO_VERSION: int`. Check it against your expected
wire version before dispatching (spec 0004 §9.3).

Full type stubs (PEP 561) ship with the wheel at
[`crates/cypher-py/python/cypher/__init__.pyi`](../crates/cypher-py/python/cypher/__init__.pyi);
CI runs `mypy --strict` against every published wheel.

### Thread safety

`CypherDatabase` is not thread-safe. Instantiate one per thread; the
per-instance cache is cheap to warm.

## 5. Tree-sitter grammar — `tree-sitter-cypher/`

A hand-maintained tree-sitter grammar kept in lock-step with the
authoritative `cypher-syntax` parser via the
`cargo xtask tree-sitter-parity` gate. Every
`outcome = "ok"` scenario in
[`crates/cypher-tck/tck/v1.toml`](../crates/cypher-tck/tck/v1.toml)
parses without `(ERROR)` nodes; every `outcome = "error"` scenario
produces at least one. Regressions fail CI.

Use tree-sitter when you want highlighting + folding **without** an LSP.
For semantic features (diagnostics, completion, goto-definition), use
`cypher-lsp`.

### Neovim (nvim-treesitter)

```lua
local parser_config = require("nvim-treesitter.parsers").get_parser_configs()
parser_config.cypher = {
  install_info = {
    url = "https://github.com/phallsignup/cyrs",
    location = "tree-sitter-cypher",
    files = { "src/parser.c" },
    branch = "main",
    generate_requires_npm = true,
    requires_generate_from_grammar = true,
  },
  filetype = "cypher",
}
```

Then `:TSInstall cypher`.

### Helix (`~/.config/helix/languages.toml`)

```toml
[[language]]
name = "cypher"
scope = "source.cypher"
file-types = ["cyp", "cypher"]
roots = []
comment-token = "//"

[[grammar]]
name = "cypher"
source = { git = "https://github.com/phallsignup/cyrs", subpath = "tree-sitter-cypher" }
```

Then `hx --grammar fetch && hx --grammar build`.

### Scope

Full v1 surface (clauses, patterns, expressions, identifiers, comments)
per spec 0001 §9 and the TCK v1 fixture. Rejected shapes (`CALL { ... }`
block subqueries, `EXISTS { ... }` block subqueries, `SHOW`, `CYPHER`
prefixes, APOC, `LOAD CSV`) fall through as `(ERROR)` nodes — spec
0001 §9.3.

Full scope list:
[`tree-sitter-cypher/README.md`](../tree-sitter-cypher/README.md).

## 6. LSP-Web — `cypher-lsp --features web-lsp`

The same `cypher-lsp` binary, compiled to WebAssembly and driven over
`postMessage` JSON-RPC. Use case: browser-hosted IDEs that want an
in-page LSP without a server round-trip.

### Build

```sh
cargo xtask lsp-web-build
```

Output lands in `demo/web/pkg-lsp/`.

### Wire up

The [`demo/web/`](../demo/web/) page has a radio toggle for
**agent-wasm** (spec 0004 §4, direct `db.check` on every keystroke) vs
**lsp-wasm** (spec 0004 §7, `cypher-lsp` running in a Dedicated Worker).
The page speaks `initialize` / `textDocument/didOpen` /
`textDocument/didChange` and renders `publishDiagnostics` notifications
as Monaco markers.

Both backends produce identical diagnostics on the sample corpus; CI
asserts this on every PR.

## 7. Stability

Every interop surface commits to a stability contract documented in
spec 0004:

- **WASM** — the agent v1 op names and required fields are frozen;
  `CypherDatabase.protoVersion()` is a runtime pin (spec 0004 §4.3).
- **C ABI** — once a symbol ships in a tagged release, its signature
  and semantics are frozen for the life of the major version (spec
  0004 §9.2).
- **Python** — wheel ABI is abi3-py310; enums over Rust
  `#[non_exhaustive]` types (severity, completion kind) are exposed
  as plain `str` so new variants don't break consumer `match` (spec
  0004 §6.3).
- **LSP-Web** — same LSP capabilities as the native server; the
  transport is the only difference (spec 0004 §7).
- **Tree-sitter** — parity with `cypher-syntax` is gated on every PR;
  drift is a blocking bug (spec 0001 §9.4).

Aggregate policy lives in [`docs/stability.md`](stability.md). The
per-surface SemVer commitments are enumerated in spec 0004; do not
duplicate them here.
