# What `cypher-sema` Checks (and What It Does Not)

> Status: living reference. Generated by walking
> `crates/cypher-sema/src/` and `crates/cypher-diag/src/codes.rs` for
> bead **cy-emb4**. The canonical descriptions live in the
> `DiagCode::E*` rustdoc; this document groups them so embedders can
> see the contract at a glance.

`cypher-sema` is the front-end's **only** semantic-analysis crate.
Anything listed here, the embedder no longer needs to re-implement;
anything **not** listed (see [§ Out of scope](#out-of-scope)) the
embedder is still on the hook for.

The crate has two modes (spec §7.1):

- **Schema-free.** Always run.
- **Schema-aware.** Run additionally when an
  [`cypher_schema::SchemaProvider`] is supplied to
  [`cypher_sema::analyse`].

Both modes share the diagnostic pipeline — embedders read codes, not
the mode that produced them.

A worked-example adapter lives at
[`crates/cypher-sema/examples/embedder_adapter.rs`](../crates/cypher-sema/examples/embedder_adapter.rs).
Run with:

```text
cargo run --example embedder_adapter -p cyrs-sema
```

---

## Pass order

Driven by [`cypher_sema::analyse`] (`crates/cypher-sema/src/lib.rs`):

1. **Name resolution** (`resolve.rs`, spec §6.2) — `E1xxx`.
2. **Kind consistency** (`kinds.rs`, spec §6.3) — `E2007`, `E2008`,
   `E2011`, `E5010`, `E5011`.
3. **Dialect gates** (`dialect.rs`, spec §9) — `E4xxx`.
4. **Schema-free type inference** (`infer.rs`, spec §7.4) — `E2009`,
   `E2010`, `E2011`, `E2012`, `E2013`, `E5012`.
5. **Schema-aware checks** (`schema_aware.rs`, spec §7.5) — `E3xxx`.
   Runs only when a `SchemaProvider` is supplied.

No pass short-circuits on first error (spec §10.4); the sink
accumulates everything.

## Schema-free checks

These run on every call to `analyse`, with or without a schema.

| Code  | Pass     | What it validates                                                                              |
|-------|----------|------------------------------------------------------------------------------------------------|
| E1001 | resolve  | Unresolved variable in expression position (spec §6.2).                                        |
| E1002 | resolve  | Variable shadows an outer binding (warning; gated by `SemaOptions::warn_shadowing`).           |
| E2007 | kinds    | Node / Relationship / Path variable used in arithmetic context (spec §6.3).                    |
| E2008 | kinds    | Variable of incorrect kind in pattern position (e.g., `Value` where node binder is expected). |
| E2009 | infer    | Arithmetic operand has a non-numeric type (spec §7.4).                                         |
| E2010 | infer    | `CONTAINS` / `STARTS WITH` / `ENDS WITH` operand has a non-string type.                        |
| E2011 | infer/kinds | `AND` / `OR` / `XOR` / `NOT` operand has a non-boolean type.                                |
| E2012 | infer    | `IN` left operand cannot unify with the right-hand list element type.                          |
| E2013 | infer    | `IN` right-hand operand is not a list.                                                         |
| E5003 | unify    | Two incompatible concrete types cannot be unified (spec §7.2 / §7.3).                          |
| E5010 | kinds    | Indexing or slicing applied to a non-list expression (spec §7.4 / §19).                        |
| E5011 | kinds    | `ANY / ALL / NONE / SINGLE` source is structurally not a list.                                 |
| E5012 | infer    | Built-in function argument-kind mismatch (e.g., `id(42)`).                                     |

## Dialect gates

These run after kind-consistency, before schema-aware. They are
embedder-tunable via `SemaOptions::dialect`.

| Code  | Gate                  | What it validates (spec §9.2 / §9.3)                                  |
|-------|-----------------------|------------------------------------------------------------------------|
| E4001 | mode rejection        | `Neo4jCurrent` dialect — not part of v1.                               |
| E4010 | `label_negation`      | `!` in label expressions; `GqlAligned` only.                           |
| E4011 | `label_union`         | `A\|B` label-union in patterns; allowed in both v1 dialects.           |
| E4012 | `integer_division`    | `/` with integer operands; `OpenCypherV9` only.                        |
| E4013 | `union_set`           | Plain `UNION` (set-semantics); allowed in both v1 dialects.            |
| E4014 | `call_procedure`      | `CALL proc YIELD …`; allowed in both v1 dialects.                      |
| E4015 | `load_csv`            | `LOAD CSV` clause; deferred.                                           |
| E4016 | `apoc_functions`      | APOC-prefixed functions; deferred.                                     |
| E4017 | `exists_subquery`     | `EXISTS { }` subquery; deferred.                                       |
| E4018 | `cypher_prefix`       | `CYPHER n MATCH …` header; deferred.                                   |
| E4019 | `call_in_transactions`| `CALL { } IN TRANSACTIONS`; deferred.                                  |

## Schema-aware checks

These run only when a `SchemaProvider` is supplied. Each one consults
the provider; an embedder's catalog is the source of truth.

| Code  | What it validates (spec §7.5)                                                                       |
|-------|------------------------------------------------------------------------------------------------------|
| E3001 | Unknown node label — referenced label not present in `schema.labels()`.                              |
| E3002 | Unknown relationship type — referenced rel-type not present in `schema.relationship_types()`.        |
| E3003 | Unknown property — key in inline pattern map not declared on any of the entity's labels/types.       |
| E3004 | Property type mismatch — literal cannot be stored in the declared `PropertyType` (e.g. `String → Int`). |
| E3006 | Unknown function — call references a name not present in `schema.function(name)`.                    |
| E3007 | Function or procedure arity mismatch — wrong number of arguments vs. signature.                      |
| E3008 | Unknown procedure — `CALL` clause references a procedure not present in `schema.procedure(name)`.    |

`E3010` / `E3011` exist in `cypher-diag` but are emitted by
`cypher schema check` (spec 0002 §9), not by `cypher-sema`.

## What `cypher-sema` does **not** check { #out-of-scope }

This is the embedder's contract. None of the items below produce any
diagnostic from `cypher-sema`, and an embedder migrating from a
hand-rolled `semantic.rs` should keep its own rules for them.

### Storage / runtime

- **Existence of nodes, edges, paths.** `MATCH (n:Person)` does not
  consult any data; it only validates that `Person` is a declared
  label.
- **Index / constraint enforcement.** Whether a property is uniquely
  indexed, encrypted at rest, or column-stored is invisible to sema.
- **Endpoint conformance at write time.** `relationship_endpoints`
  is consulted only against the *literal endpoint labels in the
  pattern* (when both ends carry an explicit label). The runtime is
  responsible for validating actual node labels at insert time.
- **Cardinality enforcement.** The `Cardinality` field on
  `EndpointDecl` is informational; sema does not reject patterns
  that would violate it. Embedders that care must enforce at write.
- **Property type at write time beyond literal coercion.**
  Schema-aware property type-checking only fires for literal values
  in inline pattern maps. `SET n.age = $p` where `$p` later resolves
  to a `String` will not be caught by sema unless the embedder
  supplies a `parameter_hints` entry pinning `$p` to `Int`.

### Authorisation, quotas, lineage

- **Per-label / per-rel-type read or write permissions.** Sema does
  not know who is running the query.
- **Procedure access control.** `ProcMode::Read | Write | Schema`
  is exposed but not enforced; embedders gate `CALL` against caller
  permissions themselves.
- **Cost limits, row caps, timeouts.** All runtime concerns.
- **Tenant / database scoping.** A query that touches multiple
  logical databases looks identical to one that does not.

### Semantics that depend on data

- **Optional path existence.** `OPTIONAL MATCH` is a structural
  rule; whether the runtime returns null or a row is sema-invisible.
- **Aggregation correctness when grouping keys are dynamic.** Sema
  validates aggregation *scope* (spec §7.3) — where aggregates may
  legally appear — not the value semantics.
- **`MERGE` deterministic-pattern rule beyond endpoint typing.** The
  schema-aware check confirms endpoints are typed sufficiently;
  uniqueness / write-visibility decisions stay with the runtime.

### Anything outside the front-end's stated scope

- **Plan equivalence, query rewriting, optimisation.** Lives in
  `cypher-plan`, not `cypher-sema`.
- **Result-set shape beyond column inference.** What a row "means"
  is the embedder's call.

## Migrating from a hand-rolled `semantic.rs`

The recommended sequence:

1. Replace any per-pass plumbing with a single
   `cypher_sema::analyse(stmt, Some(&adapter), &opts, &mut sink)`
   call.
2. Implement `SchemaProvider` against the existing catalog. See
   [`embedder_adapter.rs`](../crates/cypher-sema/examples/embedder_adapter.rs)
   for a 60-line template.
3. Wrap with `cypher_schema::StandardLibrary::wrap(adapter)` if the
   embedder doesn't ship a custom function catalog — this layers
   openCypher's built-ins on top.
4. Walk the embedder's old diagnostics and bucket each into:
   - **"Now done by sema"** — delete; rely on the codes in this
     document.
   - **"Out of scope"** (see above) — keep; add a regression test.
5. Keep `schema_digest()` honest. The embedder's adapter must
   change the digest whenever any observable surface (`labels`,
   `relationship_types`, `node_properties`, `relationship_properties`,
   `relationship_endpoints`, `inverse_of`, `function`, `procedure`)
   changes; otherwise Salsa caches stale results.
